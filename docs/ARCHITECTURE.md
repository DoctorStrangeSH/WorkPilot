# Malenia — архитектура

**Статус:** Agent Runtime 0.2 и Desktop Shell 0.3 реализованы в feature-ветках; Browser Bridge имеет ограниченный developer preview. Остальные компоненты остаются проектными.  
**Платформа первого этапа:** Windows.  
**Основной браузер:** Яндекс Браузер.

## 1. Цели системы

Malenia — персональный локальный агент, который может понимать запрос, планировать последовательность действий, использовать доступные инструменты и проверять результат.

Ключевые сценарии:

- поиск по существующим рабочим ресурсам, доступным в пользовательских сессиях;
- поиск похожих/совпадающих объектов по фотографии;
- поиск по фотографиям в нескольких внешних трекерах;
- работа с браузером и отдельными окнами;
- управление окнами, клавиатурой, мышью и файлами компьютера;
- автоматизация повторяемых рабочих процессов;
- контроль ресурсов компьютера с 16 ГБ RAM.

## 3. Рекомендуемая реализация по слоям

Окончательный выбор стека подтвердить прототипом, а не только документацией.

- **Desktop shell:** Tauri 2 + React/TypeScript — кандидат для лёгкого интерфейса.
- **Agent/runtime:** Python — кандидат для интеграций, OCR, поиска и оркестрации.
- **Local storage:** SQLite для задач, настроек, индексов метаданных и журнала.
- **Browser integration:** отдельный Browser Bridge. Проверить поддержку Яндекс Браузером расширений Chromium, Native Messaging и управляемого отдельного профиля.
- **Desktop control:** Windows UI Automation для структурированных контролов; мышь/клавиатура и скриншоты — резервный механизм.
- **Vision:** OpenCV и OCR как базовый локальный слой; embedding-модель добавляется только после измерения памяти и качества.
- **Models:** интерфейс провайдера с возможностью локальной модели и внешнего API. Ни один платный API не должен быть обязательным для запуска приложения.

## 4. Гибридная браузерная архитектура

### A. Текущий профиль пользователя

Цель — работать в уже авторизованной пользовательской сессии Яндекс Браузера, чтобы видеть только те страницы и данные, которые доступны самому пользователю.

Реализован первый preview: явно установленное MV3-расширение с `activeTab` + `nativeMessaging`, Native Messaging host и кнопка ручной передачи активной вкладки. Host сохраняет title и очищенный HTTP(S) URL (без query/fragment) в SQLite. Совместимость Native Messaging и регистрация host должны быть подтверждены на конкретной версии/канале Яндекс Браузера.

Ограничения:

- не читать файлы профиля напрямую;
- не копировать cookies, пароли, токены или базы авторизации;
- не обходить CAPTCHA, MFA, paywall, ACL и ограничения сайта;
- передавать агенту только вкладки/страницы, разрешённые пользователем;
- чувствительные операции выполнять только в рамках явных разрешений.

### B. Отдельное окно Malenia

Отдельный профиль браузера для автоматизированных задач, тестирования и изолированных сессий. Пользователь входит в сайты самостоятельно. Данные этого профиля хранятся отдельно от основного профиля и могут очищаться независимо.

### C. Browser Bridge

Текущий preview реализует только ручную передачу активной вкладки. Дальнейший целевой интерфейс для обоих режимов:

- перечислить доступные вкладки;
- получить заголовок и URL;
- сделать скриншот вкладки;
- прочитать доступное DOM-содержимое;
- выполнить ограниченное действие на странице;
- открыть/закрыть вкладку;
- сообщить о недоступности или потере соединения.

Каждая команда проходит Permission Gate и попадает в Audit Log. Browser Bridge не должен предоставлять произвольный доступ к секретам браузера.

## 5. Поиск по фотографиям

Два независимых направления должны иметь общий формат запроса и результатов.

### A. Локальные и подключённые ресурсы

1. Пользователь выбирает изображение или разрешённую папку/источник.
2. Изображение нормализуется в памяти.
3. Извлекаются метаданные, OCR-текст, штрихкоды и визуальные признаки.
4. Поиск выполняется по локальному индексу и явно подключённым источникам.
5. Результаты содержат источник, ссылку/идентификатор, оценку совпадения и причину совпадения.

### B. Внешние трекеры

Каждый трекер подключается отдельным адаптером. Адаптер использует официальное API, если оно доступно, либо браузерную автоматизацию в пользовательской сессии, если это разрешено условиями сервиса.

Нельзя предполагать единый API у всех трекеров. Для каждого адаптера отдельно фиксируются:
- способ входа и согласия пользователя;
- доступные поля и поиск по изображениям;
- ограничения частоты запросов;
- правила хранения изображений;
- обработка ошибок и изменение интерфейса сайта.

### Pipeline изображения

```text
Image Input
    ↓
Validation & Privacy Filter
    ↓
Resize / Normalize (bounded memory)
    ↓
OCR + Barcode + Visual Features
    ↓
Source Adapters (local + connected trackers)
    ↓
Deduplicate & Rank
    ↓
Results with source attribution
```

Оригинальное изображение не сохраняется без необходимости и настройки пользователя. Для временных файлов задаются срок жизни и безопасное удаление.

## 6. Полноценное управление компьютером

Desktop Automation предоставляет типизированные инструменты:

- список окон и приложений;
- получение снимка экрана;
- поиск элементов через UI Automation;
- клик, ввод текста, клавиатурные сочетания;
- управление окном;
- чтение/запись файлов в разрешённых рабочих папках;
- запуск заранее разрешённых приложений и команд.

Для каждой операции задаётся риск:
- **низкий:** чтение, навигация, скриншот;
- **средний:** ввод данных, изменение локального черновика, перемещение файла;
- **высокий:** удаление, отправка сообщения, публикация, покупка, изменение прав, массовая операция.

Низкий риск можно выполнять автоматически. Средний — по заранее заданной политике пользователя и с журналированием. Высокий — с подтверждением перед выполнением. Пользователь может отменить задачу и остановить автоматизацию.

## 7. Resource Manager: 16 ГБ RAM

Ориентироваться на фактическую доступную память, а не на фиксированные обещания по расходу.

Состояния:
- **Normal:** стандартная параллельность.
- **Economy:** ограничить параллельные задачи, выгрузить простаивающую модель, уменьшить размер пакетов изображений.
- **Emergency:** приостановить новые тяжёлые задачи, сохранить контрольные точки и предложить закрыть/перезапустить только компоненты Malenia.

Malenia не должен принудительно закрывать сторонние приложения.

Правила:
- OCR/vision обрабатывает изображения небольшими пакетами;
- модель загружается по требованию и выгружается после простоя;
- ограничивается размер очередей;
- большие файлы читаются потоково;
- все тяжёлые операции имеют отмену и контрольную точку.

Пороговые значения памяти выбираются после измерений на компьютере пользователя.

## 8. Хранилище и приватность

Локально хранятся настройки, задачи, журнал, метаданные индекса и пользовательские разрешения. Секреты — только в Windows Credential Manager или другом системном хранилище секретов.

Не сохранять:
- cookies и пароли браузера;
- необработанные токены;
- полные дампы страниц с персональными данными без явной необходимости;
- изображения пользователя бессрочно по умолчанию.

Внешнему модельному провайдеру отправляются только данные, необходимые для выбранной задачи и разрешённые пользователем. Локальная модель остаётся предпочтительным вариантом для приватной обработки, если её качество достаточно.

## 9. Наблюдаемость и надёжность

Каждая задача имеет:
- уникальный ID;
- план и текущий шаг;
- статус и прогресс;
- использованные инструменты;
- краткое объяснение результата;
- журнал ошибок;
- отмену и безопасное возобновление, если это возможно.

Инструментальные вызовы должны иметь тайм-аут, схему входных данных, проверку результата и ограничение повторов.

## 10. Нерешённые технические вопросы

- Точная версия Яндекс Браузера и подтверждённые способы интеграции.
- Нужен ли Tauri или другой desktop shell после первого прототипа.
- Конкретные внешние трекеры и разрешённые способы доступа к каждому.
- Локальная OCR/embedding-модель, которая укладывается в бюджет памяти.
- Конкретный провайдер LLM и правила расходов/передачи данных.

Эти вопросы нельзя закрывать догадками: они должны решаться прототипами и тестами.
